# 功能与评分：从行为到反馈

## 小程序规则

评分范围为 0–10，越低越好。

| 维度 | 选项及分值 |
| --- | --- |
| 出行 | 步行/骑行 0，公交 1，出租车 3，私家车 4 |
| 饮食 | 素食 0，普通 2，高碳饮食 4 |
| 状态 | 在家 1，出行 2 |

各项相加，私家车 + 高碳饮食额外加 1，步行 + 素食减 1，最后限制到 0–10。

- 树木值 = 10 − 评分。
- 基础积分 = max(1, 10 − 评分)，挑战奖励另行处理。
- 树木值 0–2 为小苗，3–5 为小树，6–8 为大树，9–10 为巨树。
- 累计积分驱动 10 级体系；成就工具定义 9 项徽章。

代码位置：utils/carbonScore.js、utils/achievement.js、cloudfunctions/common/index.js。云函数目录中的 common.js 为部署副本。

## Web 规则

Web 历史实现采用不同参数，不能直接与小程序的同日评分比较。

| 维度 | 参数 | 权重 |
| --- | --- | --- |
| 出行 | 步行 1.2、骑行 1.5、公交 3.2、地铁 2.8、出租车 6.2、私家车 8.4 | 0.50 |
| 饮食 | 素食 1.6、普通 3.8、高碳 6.5 | 0.32 |
| 状态 | 在家 2.0、出行 3.4 | 0.18 |

评分为加权和并保留一位小数。积分为 max(3, round((10 − 评分) × 3))，树木值为 10 − 评分；树木等级以 3、6、9 为边界。Python 与 JavaScript 的舍入细节也应按各自代码理解。

代码位置：backend/carbon_algorithm.py 与 src/pages/Record.tsx。后端负责实际保存时的计算。

## 反馈为什么这样组织

积分给出即时反馈，树木把结果可视化，累计等级提供长期进度，统计与历史用于回看。它们共同服务于一个持续记录循环，但仓库没有足以证明行为干预效果的原始数据。

相对评分没有真实活动量与核验排放因子，因此不是 kg CO₂ 核算。虚拟森林也不对应真实种树或碳抵消权益。

## 已知的历史实现边界

- Web 成就页有 8 张卡片，其中初次记录、连续记录、素食次数和树木数量有解锁判断；部分低碳、骑行里程、年度及分享目标仍为未完成的展示项。
- 小程序 profile 页的订阅提醒模板 ID 是占位，入口存在不等于提醒服务已经完整配置。
- Web 低碳问答使用本地关键词和知识规则，没有远程大模型调用。
- 两端身份、存储和评分参数独立，未实现账号绑定与数据互通。
- 社交社区、企业报表、商业化、碳普惠与校际联盟等旧方案未作为公开版本的已完成功能列出。

这些边界按源码记录。开源整理保留历史状态，不重新开发或补齐上述能力。
